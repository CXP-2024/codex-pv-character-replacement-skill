# 失败经历与改用方法

下表汇总实际返工模式；症状来自用户反馈，具体根因须用 raw、映射、合成与成片确认，不能凭截图一律归因于 H3 或替换。方法有适用条件，不构成自动修复保证。验收集中在 [quality-control.md](quality-control.md)。

## 人物、表演和画风

| 反复出现的问题 | 失败做法或待查层 | 有效路线及边界 |
|---|---|---|
| 头突然短一截、脸像被打歪 | 非等比配准、局部贴脸与原轮廓不符 | 先查raw；重建完整同姿势绘稿，不以扭脸降低差值 |
| 双层头发、切镜发型变化 | 旧头发未清、人物身份版本不一 | 统一认可正侧参考，清完整旧轮廓；不可分离则整人物重做 |
| 眼变异、瞳色在正侧镜头间变 | 低像素raw、错身份锚、固定眼贴片 | 增加人物输入像素预算；完整小脸及刘海一起验，只改瞳色时约束虹膜 |
| 面部像目标但看错方向、歉意变普通低头 | 身份盖过源表演 | 身份与视线/眉眼/嘴形分别约束；参考清楚也不能抹掉原神情 |
| 嘴歪、过锐、微张被当后退 | 口型表粗糙、嘴坐标/采样不符 | 源口型逐帧定标；同姿势局部嘴仅在允许时用，实际尺寸匹配清晰度 |
| 拉近运镜中嘴反复位移 | 相机与头部坐标混用、逐帧bbox抖动 | 在头部坐标放嘴，统一变换一次；头姿变就换完整绘稿 |
| 纯平移镜头角色变形、头发颤动 | 给静态绘稿自由生视频 | 完整画幅重绘一次，再复刻原平移；不能冻结独立粒子 |
| 点头像向右扭头、抬错手 | 只比头中心或总体位移 | 对齐方向、幅度及肩手衣服联动，按真实动作筛H3帧 |
| 动作可用但变得太快、静止者晃动 | 均匀抽帧/复用模型原速度 | 原事件表＋单调选帧＋原曝光长度；逐人物核对 |
| 前后静帧与中段H3画风突变 | 独立图像锚与视频raw混用 | 两侧确实静止时可用同一认可H3序列实际稳定帧；全段检查配色 |
| 多轮修脸更碎、更油 | 在失败生成图上反复编辑 | 回原片同帧直出并明确身份/画风职责，别叠加补丁 |
| Q版首尾粗线、中间细线；呆毛变圆环 | 上游形态定义/视频中间绘稿失控 | 独立Q版身份锚，检查每个真实状态与轮廓；不能只验端点 |

## 合成、背景和漏检

| 反复出现的问题 | 失败做法或待查层 | 有效路线及边界 |
|---|---|---|
| 气泡相位跳、墙壁位移、灯光一帧闪 | 背景跟人物换稿、来源/配准不一 | 背景按自身时序连续播放，拆开相机、人物和背景变化 |
| 皮肤变暗、嘴边脏块、粉发残影 | 全局调色遮接缝、旧区域没清净 | 查最早变色层；分别清理旧人物包络、校皮肤/虹膜，不压暗全镜 |
| 发饰中间帧消失、头发被切、底部黑边 | matte漏边或外裁切覆盖不足 | 看全运动包络、遮挡和四边；扩边/修matte，不裁掉坏处 |
| 眼嘴清楚但颊边长尖刺、衣服穿模 | 只检器官，未检邻接结构与遮挡 | 看完整脸/全身与所有轮廓；重复结构失败就换完整绘稿路线 |
| 两侧斜黑影修过仍闪 | 宽保护区保留坏背景，裁切/人物层带不同底色 | 看保护区里的空背景、内外边界和供体；只回填确认空背景，不能仅加羽化 |
| 背景MAD下降仍有接缝 | 平均稀释小缺陷；QC遮罩与制作遮罩同源 | 分区热图、局部高分位/连通带、可信稳定帧对照；独立查看遮罩 |
| 一直存在的黑条没报错 | 只看相邻帧差值 | 加空间边界检查与稳定背景/供体对照，时间稳定不等于正确 |
| 背景差值高峰其实是头在动 | 背景ROI混入前景 | 检查ROI实际内容和坐标映射，再解释指标 |
| 模板修好但后面认可动画被覆盖 | 修复范围扩张、旧脚本/选择回退 | 以最新认可底片为基准，显式区间与优先级，验证范围外 |
| 模糊或溶解后指标变好但双眼/双发 | 不同姿势强行混合 | 可信端点连续桥或完整绘稿；不以平均差值作美术评分 |

## 其它制作与工程失败

| 问题 | 改用方法 |
|---|---|
| 背景旁人变脸、无角色镜头冒出人、场景穿错衣 | 只放当前cast参考，分别约束身份/保护角色/场景衣装 |
| 跑步像漂移、多层名字卡冻结 | 腿部节拍和各层路径分别复刻；静图平移不冒充真实动作 |
| Logo淡出后返影、字边破碎 | 清完整残留尾段，独立透明文字资产与实际alpha合成检查 |
| 清晰度提高但坏眼更明显 | 原生先修对，SR不能修身份；既有原生画面不降采样再SR |
| 裁切/加速重复计算，开头字幕漏掉 | 记录每个素材已执行的变换，统一时间轴公式；跨裁切点字幕截断而非删整句 |
| 字幕重叠被一刀切删除 | 核对正文、说话者、声音和时间；只删除确认重复/用户指定项 |
| hash都正确但仍装旧版 | hash只保完整性；检查当前选择、撤回与替代关系 |
| raw完整而任务failed | 查CPU QC/编码/父子ID，只恢复坏环节，不盲目重跑GPU |
| H3无OOM却长时间不动 | 核查共享显存溢出、所有队列与锁，按后端实测恢复 |

## 这次复盘改变了什么

旧规则的“逐帧检查”过于笼统，且路线、检查、资源规则重复分散。现改为：入口选路线 → 源事件/曝光 → 有边界的制作 → 独立空间与时间验收 → 最新母版回填。

减少重复提醒不等于删除证据。具体帧号、私有素材、失败候选和修复脚本留在项目；公开skill只保留可复用判断。最后一次背景修复仍须区分技术检查与用户认可，不能因导出成功推导最终美术通过。
