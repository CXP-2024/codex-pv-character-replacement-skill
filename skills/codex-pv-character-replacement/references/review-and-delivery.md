# 检查、返修与交付

## 检查真实画面

先定位最早错误层：`原片 → 起点图 → H3 raw → 选帧/曝光 → 合成 → 可选超分 → 编码文件`。raw 已正确就修下游。短返修段检查全部变化帧，连同前后接缝；长片保存覆盖记录。全画面、目标局部和邻接轮廓都要看，不能仅看首中尾。

| 项目 | 重点 |
|---|---|
| 身份/画风 | 眼睛、刘海、发量、饰品、头身比、身高、裙长和同一件衣服；正侧背视一致 |
| 动作 | 睁眼与口型、手指/手腕接触、拍打相位、点脚落地、重心；有风的头发衣服确实运动 |
| 构图/遮挡 | 源画面位置、尺度、裁切；手指不被 matte 截断，人物不穿过树干或前景 |
| 光效/背景 | 地面、树木和光斑不跳；投影、遮盖→显现、曝光与原片时序相符 |
| 接缝 | 人物设计、姿态和明暗不重置；重叠只选一份，原本的切镜/白闪保留 |

差值和跟踪用于定位，平均低分不能排除单眼、细黑条或恒定接缝；独立查看遮罩内外和四边。源身份与目标不同，不追求整图像素差为零。用正常速度检查观感；无法播放时记录连续帧检查范围，不声称已观看播放。技术通过、人工观察和用户认可分开记。

## 第 4 关的八项指标（每镜交付前必出）

第三段用户指出的模糊、单帧残影、背景闪烁、1 px 抖动、动作僵硬，我的检查都没拦住：联系表缩到 240–320 宽、每 4–12 帧抽一张，这些问题在缩略图上看不出来。每镜交付前先跑下面八项，超标的帧修掉再交，或在交付时直接问用户。后三项来自一部二创短片：用户连续看时发现的取景偏移、卡住、单帧停顿，抽帧审都没拦住。

| 指标 | 怎么量 | 超标线 |
|---|---|---|
| 背景稳定度 | 固定机位镜头：逐帧量背景区域（避开人物，如天空上半部）的相邻帧差，必要时加相位相关位移 | 超过原片同帧的 2 倍；位移来回超过 0.5 px（原片背景通常只有胶片噪点，约 1–2） |
| 清晰度 | 人物区域的拉普拉斯方差，除以本单元中位数 | 低于 0.6 |
| 接缝跳变 | 每个单元交界、每处接缝的整帧帧差和背景帧差 | 超过原片同一帧的 2 倍（实测曾有天空跳 7.2，原片 ≤1） |
| 残影/多余人物 | 原片里人物已淡出或不在场的区间，量对应区域和原片的差 | 出现原片没有的轮廓即不过（实测 GLM 淡出后又回来 3 帧） |
| 外观尺寸 | 发尾位置、头顶高度、饰品是否连在头上，和规格书、关键帧比 | 发尾越过规格书写的部位；饰品脱离头部 |
| 引导帧处的取景偏移 | 每张引导帧（含结尾）前后 ±3 帧：帧差，加背景区域的相位相关位移 | 帧差超过原片同处 2 倍；背景位移明显大于原片（实测帧差只有 11.1 的一处取景整体偏移，用户一眼看出） |
| 冻结帧 | 每镜里画面完全不变的连续帧（整帧和每个小块都不变） | 有人物的镜头连续冻住超过约 1 秒（实测 42 帧静帧被说"很卡"）；照抄的定格落在我们画面在动的地方 |
| 运镜中的单帧重复 | 镜头在动时，孤立的一帧和前一帧相同 | 出现即不过；多半是转帧率补出的重复帧被当成定格照抄 |

**固定的看图方式：**
- 转场和接缝前后 ±8 帧，原片和新版全尺寸逐帧并排，一帧不跳。
- 快动作、远景小人物裁到人物区域放大看。
- 不用缩小的抽帧联系表下"已对齐"的结论；它只用来找可疑区间。
- 指标通过后再按正常速度连起来看一遍。

## 交付前全片检查（每一版都跑，2026-11-22 起）

一支 69 秒的换角片，v1 交付后用户指出"还有原片""很多突变"。下面三项当时任何一项先跑过，都能在交付前查出来。

1. **`scripts/cut_audit.py --src 原片 --cut 成片 --ledger 帧台账 --bounds 分镜点`**
   - 保留原片的范围外有没有原片帧（台账核对）。
   - 每个分镜点和每个原片跳变：前后是不是同一张画（相似变换内点数、缩放倍数），分镜点是否落在 ±4 帧内最大跳变那一帧。
   - "我们跳了、原片没跳"的帧（我们的相邻帧差比原片大 40 以上）逐个看：多半是链尾变样、时机差几帧，或者一张画拼了两张关键帧。
2. **全片每 4 帧一张的原片对照联系图**（上原片、下成片，标镜头号和链号）。
   - 每镜抽 8 帧的审片图拦不住：实测两处变回原片人物，一处在倒放链最后 4 帧，一处在人物跑远变小、被前景挡住的几帧。
   - 重点看：链尾、人物变小或被挡、多人同框、黑帧之后。
   - 保留原片的范围另出逐帧联系图，看有没有人。
3. **`scripts/camtrack.py --src 原片 --cut 成片 --range s e`**：每个有运镜的镜头，逐帧比较缩放和位移的方向。原片单向、我们来回或反向的，退回链构造那一层重做。

## 整帧效果清单（合成时做，用户同意过的才用）

原片的整帧效果按开工时的"切换点清单"在合成时做。只做整帧运算：不变形、不贴图、不加遮罩。H3 生成的人物像素一律不动。

| 效果 | 做法 | 注意 |
|---|---|---|
| 黑白闪 | 灰度后按阈值二值化，阈值和黑白方向逐帧按和原片同一帧的相关性选；细线稿（灰度低于自身模糊版 18 以上的像素）用相反颜色叠回，脸才认得出 | 只做二值时人物会变成一团剪影 |
| 淡出淡入 | 每个通道用"原片这一帧相对淡出前最后一张全亮帧"的分位数曲线，查表套到我们的帧上 | 淡出后面常跟着下一镜的淡入，两边都量；淡出不是整体乘一个系数，暗部掉得更快 |
| 相对淡出淡入 | H3 自己已经亮暗了一部分时，经过我们自己的全亮帧换算：每个分位数，把我们这一帧的值映射到"原片曲线作用在我们全亮帧对应值上"的结果 | 直接套曲线会暗两次或亮两次 |
| 闪白 | 均匀向白退：255 − (255 − 帧) × a，a 让整帧均值等于原片那一帧 | 分通道曲线会偏色（实测人物泛青） |
| 甩镜、渐糊 | 以横向为主的盒式模糊，逐步加宽，直到我们这一帧的清晰度（灰度 Sobel 幅值均值）不高于原片同一帧 | 只按中间调比例停止会糊得不够 |
| 时机对齐 | 选帧：只换某一帧用链里的哪一帧（REMAP），不改像素。例如原片在 1456 帧扫镜、H3 在 1460 帧扫，就把扫镜那几帧挪过去，后面的帧均匀摊开 | 不跨原画换画处乱挪；原片停住的帧可以跟着停 |

**不做的事**：
- 用整帧缩放裁切 H3 输出帧去模仿原片的数码缩放：用户 2026-11-22 否决。H3 跟不上缩放就放弃缩放。
- 两张不同的图做像素叠化，例如画面溶进字卡：要做就先问用户。实测改用"相对淡出"往字卡的亮度靠，不叠化。

## 去鱼鳞纹与光照

GPT / Codex 出的二次元图（关键帧、逐张重画帧）带细密的鱼鳞状碎纹，不能当作细节保留。人眼在原尺寸下看得出，但放大、高通滤波、频谱分析都不容易查到，**不要自己判断"这张没有噪点"**。

每张要进 H3 或成片的 GPT 图，都用去鱼鳞纹 skill [gpt-anime-denoise](https://github.com/CXP-2024/gpt-anime-denoise) 跑一遍。安装时把整个仓库放进 skills 目录（Claude Code 的 `.claude/skills/gpt-anime-denoise/`，或 Codex 的 skills 目录）。

```bash
python <gpt-anime-denoise 目录>/denoise.py <图片或文件夹>     # 默认 esrgan60_l0：ESRGAN 缩到 60% 再放回 + L0 0.001
python <gpt-anime-denoise 目录>/denoise.py <图片> --all       # 7 种候选 + 原尺寸 4×2 并排对比
```

- **顺序：** 出图 → 去噪 → 关键帧自检（第 2 关）→ 用户审静帧。自检和 HSV 测量都用去噪后的图。
- **默认交付 `esrgan60_l0`。** 纹理还残留时，把 `--l0` 调大到 0.0015–0.002；淡阴影、腮红被抹平时，调小到 0.0005–0.0007。
- **给用户挑时发原尺寸并排图，** 不发放大的局部。
- **不用扩散重绘、导向/双边滤波或全局模糊代替。** 前两种会重画眼睛，后两种会把轮廓、大块阴影和明暗层次抹掉。
- **依赖：** torch + spandrel，模型第一次运行时自动下载。也有网页工具 `denoise_app.py`，可以只给局部去噪。

若 raw 人物曝光突变，先从前面的可靠 H3 状态续跑并约束原光照。不要用后置硬人物遮罩把整个人压成剪影来掩盖失败；用户要撤掉遮罩时也检查底层 raw，不能撤掉后留下原来的闪亮跳帧。

## 文字、Logo 与原片复用

每段标明歌词、水印、标题、staff、环境文字的 keep/erase/replace。按项目要求去除；一旦要求全片无歌词/水印，原片直用段也不能漏检。清理范围覆盖移动边界和消失尾巴，不靠 OCR 一次扫描或初始矩形免检。

保留动态原片时只修需去字的区域，检查文字跨人物/衣物的部分。去字失败而必须改用 H3 时，仍按单镜头连续链处理。不能为了无字把动态片段换成静止封面，除非用户明确选择这种播片方案。

标题/署名用独立透明图层：相同 Logo 优先提取或复用原字形，小号文字优先实际字体排版。逐字核对、检查真实 RGBA、位置、大小、斜度、投影、出入场与遮挡。未知字体只说样式匹配，不能声称鉴定了原字体。开篇标题需跟随原动效，不能只贴静态最终图；在最终尺寸叠字，字层修改不重跑正确的 H3。

## 回填与交付

1. 冻结当前选用基线和修复范围。逐帧台账记录源帧/PTS、实际 PNG、模型索引、hash、图层及版本；每个源时刻有唯一有效选择，旧失败候选不自动回填。
2. 修复无损素材后，验证范围外资产/hash 或像素不变。一次只升级所需下游；原生直用画面不先降清再超分，超分按当前约定执行，不能用插值缩放冒充模型超分。
3. 从直接解码 PNG/原生素材制作成片，保留无损序列供最终母版。预览采用用户设备兼容编码；本次经验为 MP4/H.264 yuv420p + MP3 音频，不把它强制成所有项目默认。最终无损交付另按约定导出 PNG/FFV1、PCM/FLAC 等。
4. 保留约定的原音轨与源时间。加 BGM 与替换人声分开，不能误删对白；裁切、变速及字幕时间只变换一次，核对起点、拼接和尾句。音频不覆盖全片时先明确剩余段处理。
   - BGM 在开工前定（见 [preproduction.md](preproduction.md) 生产参数）。要把歌剪短时，接点选在歌曲自己会重复的地方（例如副歌接副歌）：用频谱互相关量出两遍之间的精确间隔，接上后等于原曲里本来就有的一处接缝（实测误差 5 ms），加 30 ms 交叉淡化。让歌的自然结尾落在画面淡出处，不在歌中间硬淡出。
   - 响度统一到约 -14 LUFS，只调增益；网上搬运的 DJ 版常已削波。
5. 核对真实编码、尺寸、精确 fps/PTS、帧数、时长和音轨，全文件解码。回读实际输出并核对本次修复帧、接缝和文字；编码正常不等于美术通过。
6. 输出原片/新版并排帧号对比与纯成片，报告检查范围和实存差异。交付完整后再推进最新版本指针；保留前版、锚点、采用 H3 PNG、链记录与脚本。

具体角色表、原片、完整日志、私有路径、服务地址和素材留在项目；skill 只保存可迁移的方法。
