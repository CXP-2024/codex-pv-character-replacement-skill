# 原生底片、超分与成片

## 帧台账先于装配

每个最终A帧记录实际资产、资产内帧号、hash、源区间、selected版本、原生尺寸、是否SR、图层。逐帧覆盖目标范围，禁止空洞、重复或静默回退。拆段重叠通过明确优先级/bridge映射展开成唯一最终行，不按文件名排序猜。

完整片与独立片段都保留A帧：独立输出第0帧可以对应A1392，元数据写明，不改称A0。仅将编码PTS归零。

临时装配允许原片占位时明确标placeholder；不能混进声称替换完成的交付。通过的copy镜头是有意保留，不是占位。

## 全分辨率底片

从H3原始native_frames/无损序列构建单画面，绝不裁切“1920宽并排预览”的右半当1080p底片。列标题和帧号栏不是影像资产。

- H3低清新帧：运行选定SR，必要时2×后缩回目标1080p。
- 原片copy或已有原生1080p片尾母版：直接使用，不先降到576p再超分。
- 新名字/Logo/staff：在最终尺寸后叠，不送SR改字形。
- 只修一段：那段按完整流程重新生成/还原原速/SR/文字重合成，再回填最新母版。
- 修ROI：只SR局部，窗外保留原1080p，记录位置、边缘羽化及遮挡策略。

SR在H3队列真正空闲、卸载后执行，共用GPU锁。不同模型速度/画风必须实测，别用原片降采样测试代替真实H3的破线/抖动测试。选型依据线条、脸、配饰、运动稳定性；PSNR高或更锐不等于更像原片。默认不增加帧率。

若指定SR跑不通，保留原生底片并报告；不能悄悄用插值缩放冒充模型SR。

## 分层装配与局部不回退

固定baseline文件hash，应用有序patch清单，区间统一半开。用户给闭区间需明确转换，例如A2057–2097含两端→[2057,2098)。

顺序：原速画面/转场修复→有证据的hold同步与轻调色→需要的SR→原生1080p直通拼接→全时间线文字/Logo/片尾覆盖→音轨→编码。

大型片尾母版也需检查第一/最后帧：可能带旧Logo或下一场原人物。不能因它被叫master就免检。未知冲突报告，不篡改受保护导演素材。

无损逐帧核对patch外与baseline像素相同，patch内与指定新帧相同。有损MP4重编码后只用相应误差统计，不能要求原压缩文件hash相等，也不能宣称逐像素一致。

## 输出与同步

推荐无损母版PNG/FFV1（像素格式明确）、音频PCM/FLAC；预览H.264 yuv420p、例如CRF18 + AAC。参数按用户交付平台调整，不重复有损转码叠加。

保存视频fps为有理数、frame_count、time_base、start_time，音轨起点与时长。AAC封装可能有编码延迟，不只比较容器总时长。正确截取原曲范围，独立彩蛋用对应源起点，不用整曲从0秒重放。音频流复制需确认切点/PTS可行。

核验：
1. 全段解码，无缺帧；尺寸、fps、帧数符合计划。
2. 原速预览边界、白闪、首尾、声音同步。
3. 实际回读最终编码的关键帧，不只看编码前PNG。
4. 全屏/局部小脸、文字alpha和渐隐尾巴检查。
5. 工程完成、抽检范围、用户审片状态分开写。
