# H3 单镜头接续

## 起点、动作与参考职责

使用原片同帧编辑出镜头起点；不要在反复失真的旧 AI 图上堆修。检查脸型、瞳色、发型、头身比、服装和配饰；场景衣装是否保留由项目约定决定。群像写清画面位置、前后层次及各人的源→目标映射，包含背影、剪影和背景人物。

每段输入职责固定：

| 输入 | 职责 |
|---|---|
| 原片对应短段 | 原表演、相机、背景、光效与遮挡时序 |
| Picture 1 | 本段真实首帧：首段为已检查的 ImgGen 图，续段为实际 H3 输出帧 |
| 可选 Picture 2 | 同一镜头原始认可图或身份参考，仅帮助遮挡后恢复外观，不是第二个时间锚 |

默认只把 Picture 1 接入首帧 guide。增加外观参考时，核验文件复制、参考顺序、节点和 conditioning 确实进入实际工作流；不要只改 prompt。参考图数量不是质量保证。

外观参考也可能带入姿势。实测中，低手位的 Picture 2 虽修好了遮挡后的背景身份，却让后续固定手位的对白段反复降手；当人物已完整露出时，去掉该参考、只用经过检查的实际接续帧，才保住手位。不要为每一段机械保留所有参考，删图时同步删除 prompt 中对应编号。

## 接续规则

1. 检查前段输出，选择最晚的可靠帧；尾部已漂移就向前退，不机械选最后一帧。保存直接解码的 PNG，不能从并排审阅视频裁出画面当母版。
2. 记录 `parent_job`、`parent_model_frame`、`anchor_source_frame`、原始 PNG 路径/hash 与源事件。下一段 source 从这个对应时刻开始，不能取模型 M40 却标成别的源帧。
3. 原图画布完整映射到后端输入；分辨率改变时避免默认中心裁切，保留全图比例与记录的缩放策略。不要无意裁掉手指、鞋底或裙摆。
4. 下一段继续原动作与当前光照，不重新做开场、摆姿、淡入或定格。遮挡后的外观恢复沿用同一镜头设计；不要把外观参考的姿势/背景搬回来。
5. 检查接缝前后与重叠帧，按源事件选定唯一输出。用实际接续解决断层，不靠交叉淡化、贴脸、非刚性扭曲或压暗人物遮住问题。

链式示意：`ImgGen A → H3 段1 → 实际帧 B → H3 段2 → 实际帧 C → …`。B、C 都是经过检查的模型输出，不是按源帧另画的独立图。同镜头共用原始外观图不等于新增时间锚。

可保存以下链记录，字段可适配现有工程：

```json
{
  "job": "shot12_part2",
  "source_span": [148, 201],
  "anchor": {
    "kind": "actual_h3_frame",
    "parent_job": "shot12_part1",
    "parent_model_frame": 55,
    "anchor_source_frame": 148,
    "path": "shot12_part1/lossless/M055.png",
    "sha256": "actual-file-hash"
  },
  "selected_span": [149, 201]
}
```

原始锚文件与后端预处理后的文件分别留 hash。锚点共同曝光可只选一次，接缝无需重复插入首帧。

## 分段接续的实际做法（2026-10-26）

- 每个镜头的锚定段（A）包含已审 ImgGen 锚点，guide 放在锚点对应的模型帧；之后每个前向段（F）从上一段最后一个已用源帧开始，Picture 1 取上一段该帧的实际无损 H3 输出，guide 放在第 0 帧，与上一段重叠 1 帧，从第 1 帧起采用。
- 锚点之前的部分用倒放段（B）：参考视频把源片倒着播，Picture 1 取父段在起点处的实际帧，生成后再反转回来。
- runner 按依赖顺序执行：父段完成才跑子段；父段失败则子段一并标记失败。子段的 guide 图在云端直接从父段的无损帧中取，不经过本地往返。
- 少于约 5 个源帧的倒放段（如只有 1 帧）容易和父段产生跳变，这一帧直接沿用父段首帧更稳。

## 提示词：只写镜头里真实出现的人，只用正面描述

第一版提示词把三个角色全写进每个镜头，还加了“不要尾巴/翅膀/女仆头饰”。结果在单人特写里凭空生成了另外两个角色，还给她们穿上了女仆装，因为否定句反而把这些东西带进了模型。改为：只描述该镜头实际出场的角色；服装写成“穿 Video 1 里的舞台服”；结尾写“只出现 Video 1 里可见的人”。之后不再出现多余人物。

## 不要用多张独立生图锚满整个镜头（2026-10-26）

H3 偏离时，第一反应不应该是每隔 6–12 帧画一张 Codex 关键帧、作为多个 guide 锚满全镜头。这违反“一个镜头一张 ImgGen 起点，其余从已检查的实际 H3 帧接续”的规则：每张独立生图都会带来自己的细节差异，同一镜头内部也会产生跳变（实测一个短镜头加三张关键帧后，人物在中途突变）。顺序应该是：
1. 起点锚本身错了（例如继承了原片发型），就重画这一张起点，然后整镜头重新接续。
2. 镜头短（不超过约 39 帧），就整镜头一次跑完，只用这一张锚；可以多试几个 seed，挑稳定的一个。
3. 接续中途偏离太多时，才在失败的那一帧重新锚定一次，并告知用户。
另外：GPU 不能在等决策时空转。小的外观瑕疵问一次，用户说用现有的就立即提交。

独立生成的帧同样不要直接拼进 H3 帧序列。实测把三张 Codex 重画帧贴在镜头开头后，人物在接缝处明显突变，撤掉后整镜一次跑完才解决。

## 快速动作与 H3 的边界

镜头里有快速动作（手从脸前一扫而过、高速甩头发、闪白、急速摇镜）时，H3 常常画成一团模糊、提前或推后几帧，或者干脆漏掉（例如举起的手消失、蹲着没站起来）。处理方法：
- 个别画错的绘稿：在该源帧上用 Codex 局部或整帧重画（以原片同帧为构图底，以同镜头已审的 H3 帧为画风参考），按原片的一拍二曝光贴回。
- 整段停在锚点不动（应有的转头、头发扫过都没有）：先换 seed、换锚定时刻或拆短。仍不动时，才用少量关键帧带多个 guide（`additional_anchors`，各放在对应的模型帧）重跑这一段。这是最后手段：它能救回动作，但会牺牲同镜头一致性，要逐帧检查，并告知用户。
- 淡入淡出和闪白：在合成时按原片的亮度曲线补上，不必重跑。
- 跨镜头叠化：不要在合成时做像素混合，用 H3 过渡段，Picture 1 取前一镜实际帧，末帧 guide 取后一镜实际帧。

## 审片工具的帧对齐

逐帧对照原片时，源片解码必须用 `trim=...,setpts=PTS-STARTPTS`，并加 `-fps_mode passthrough`。否则时间戳会让 ffmpeg 补帧或丢帧，对照图整体错位，看起来像 H3 动作时机不对，其实是审片工具的错（曾把正确的手部动作误判成时机错误）。

## 时间对齐

源区间、模型帧率/长度和最终曝光分别记录。均匀重采样只生成候选：模型可能提前遮挡、迟睁眼或改变拍手相位，不能据映射公式宣称动作还原。

逐项对照动作方向和幅度、眼睑/口型、手部接触、脚掌落点、人物位置、树干进入/离开、投影及白闪。选择保持时间顺序的模型帧，保留源片真实静止曝光；持续运动的背景与光效不能跟人物一起冻结。需要跳过多段动作才能勉强拼接时，回到较早可靠帧重跑。

快速动作的提示词先由源逐帧核实：例如前脚离开后，后脚可能立即跟进，不能只根据首尾接触表把后脚写成全程支撑。质量审阅同时检查提示词是否把源动作描述错了。中途锚定的张嘴或低手姿势也可能锁死整段；整镜被退回时，优先恢复真正首帧，再检查动作，而不是仅检查角色相似度。

提示词事件时间按实际送入模型的视频计算。模型总时长 `g/fps` 与末帧 PTS `(g-1)/fps` 分开，原片时间不能直接套进拉伸后的模型时间。

参考视频必须解码核验实际帧数。H3 Ref2VA 至少需要 5 帧；源片只剩 4 帧时，补真实末帧保持再提交，最终仍按源片采用 4 帧。实测 `trim`、`setpts` 与 `tpad` 写进同一过滤链不能代替成品解码检查；短参考未补齐还可能被模型拉长动作。需要补帧时对已导出的短片再执行末帧保持，并核对实际输入与生成长度。父段动作被模型延迟时，接续锚要同时记录模型索引、原名义时刻与逐帧核对后的源动作时刻，不能伪称索引天然一一对应。

## 何时重新 ImgGen

先排查输入锚、实际 guide、源区间与像素预算，从最后可信 H3 帧缩短续跑并写清失败动作。相同故障仍不能改善时判断：

- 真正切镜出现新人物、场景或新构图：用原片新镜头同帧建立新起点。
- 同镜头变化过大，H3 持续恢复原人物、失去衣装/结构或无法到达所需视角：在实际失败的源姿势重新锚定，注明中断原因，再从新锚启动连续链。
- 首锚画风/人物本身错误，或整镜被退回：重做该镜头起点，替换依赖旧起点的后续链，不接回已拒绝的旧图。

重新锚定后仍检查交界；它是失败后的恢复手段，不是每隔固定帧数补图。模型状态失控不能靠增加更多独立锚或无限换 seed 解决。

## 提示词与后端

Ref2VA 使用后端支持的六段结构：`subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。主体定义区分原演员提供表演、目标提供外观；摘要采用视频编辑/外观迁移语义。保留分析写清源身份被替换，不能把整个原视频标成无条件 fully_preserved。

详细描述包含：从 Picture 1 原状态接上、当前段具体动作与光效、目标稳定特征、原切镜/遮挡、去字要求。不要重启参考图的动作；不新增原片没有的动作或相机。默认生成无声画面，装配时接项目音轨。需要其他模式时使用环境中的 `h3-prompt-writing` 或实际后端 schema，不将 Ref2VA 的源视频约束误套到 FL2VA。

沿用已验证环境，有限显存可分编码缓存→实际卸载→采样/解码。缓存须完整保存 conditioning 与 AV latent，并验证嵌套结构和 tensor 往返。配置、源片段、prompt、参考顺序和实际工作流冻结；后端参数以真实小样为准。

GPU 提交使用现有队列；有 `render-submit-queue` 时按其规则检查物理 GPU UUID 锁、服务队列和进程。服务失联先查真实进程，不盲开重复服务；显存释放以实际占用为准。只恢复自己的失败提交。raw 完好而 CPU 检查/编码失败时，只补失败的下游步骤。
