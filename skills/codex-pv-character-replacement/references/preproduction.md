# 开工前锁定：规格书、测量表、生产参数

来自一支 1 分钟、五人替换的试点（2026-11）。全片返修约 32 轮，按最早出错的那一层归类：

| 原因 | 约占 | 例子 |
|---|---|---|
| 规格没先定 | 一半 | 没有背面设定，背影头发改了七八次；发色没有数值；小脸分辨率没定；参考图截得比例不对 |
| 已有规则没执行 | 三分之一 | 关键帧没和定稿比就进 H3；没给用户审静帧；连续运镜拆成多个起锚单元；手动改色 |
| 模型做不到，事后才发现 | 约 15% | 小尺寸口型、快速转身、素描叠化、多层运镜 |

最后一次返修按这里的流程走（参考图按比例截 → 静帧审 → H3），一次就通过了。

## 1. 角色规格书

每个目标角色一页，用户认可后存档。之后的关键帧都拿它逐项比。

| 项 | 写什么 | 例子 / 教训 |
|---|---|---|
| 定稿图 | 正面、背面、侧面，同一画风 | 只有正面时，背影的发型、长度、发饰位置全靠模型猜。一个背影镜头改了六次还在变，补了背面定稿才稳住 |
| 头部特征 | 耳、角、发饰、头饰：形状、颜色、在角色自己的哪一侧 | "外卷带棱节的角"，不能只写"角"；背面看左右互换，在背面图上标出来。曾把蝴蝶结画到另一侧 |
| 颜色数值 | 发根和发梢、瞳色、肤色的 HSV 中位数，从定稿实测 | 关键帧色相差 ≤5°，饱和度、亮度差 ≤10（0–255）。H3 出片通常比关键帧暗约 10 级，属于正常 |
| 头发长度和形 | 发尾到身体哪里（肩/背中/腰），发尾下面露出哪些部位；发束的画法 | "几大块顺滑发束、接近竖直下垂、平涂"。不写的话，模型会画成很多细卷、往两边张开。这一项要原样写进每段 H3 提示词的"外观锁"，否则背影会越跑越长（第三段实测盖满后背） |
| 小尺寸画法 | 脸宽约 100–200 px 时眼睛和嘴怎么画、嘴里的颜色、线条粗细 | 嘴里写成浅粉，不画深红"D"形；线条同原片细浅线 |
| 服装约定 | 保留原片服装还是换装；哪些不要 | "原片校服 + 设计图头部全部特征，不要尾巴、不要背后翅膀" |
| 脸型 | 照被替换的原角色，还是照目标定稿 | 五人用同一张底图出定妆，脸型会变成一样 |
| 认可记录 | 日期、文件名、认可人 | — |

## 2. 镜头测量表

每个镜头一行，**从原片量出来，不凭印象写**。项目里存成数据文件，例如 json，提示词和审片都从这里取数。

| 列 | 怎么量 |
|---|---|
| 范围 | 零基半开区间；切镜对照画面确认 |
| 在场角色 | 每个角色在画面里的帧区间，含入画、出画帧 |
| 构图 | 目标角色头宽占画面的比例、头部中心、头顶是否被切、底边到身体哪里、看得到哪些部位 |
| 运镜 | 逐帧位移。大块白衬衫等低纹理画面里相位相关会测错，要人工看。前景人物和背景移动量不同就是多层运镜 |
| 表情 | 放大原片读，写具体，例如"惊慌大喊，眼睛藏在刘海阴影里" |
| 口型 | 逐帧档位，例如闭 / 小圆 / 扁细 / 扁宽，以及眨眼帧。位置用眼、鼻模板跟踪，固定裁切框在运镜时会漂（实测漂约 40 px） |
| 原画节奏 | 一拍几；哪些区间是同一张原画的定格（对齐后帧差 <1.5） |
| **结构分类** | 必填，测法和做法见下方"结构分类"表 |
| **相邻镜头共用背景** | 必填。量交界处背景区域（避开人物）的帧差，<2 就是同一镜，一条链做完 |
| 配角 | 镜头里每个非主角（家人、同学、路人）：换不换、换成谁、在哪几帧出场。每段开工都和用户确认一次 |
| 难点标记 | 对照第 5 节，标出的镜头和用户事先定做法 |

### 结构分类

逐帧实测（全分辨率，去掉四边 20 px），按下表归类。分类结果每镜一句"原片怎么做的、我们打算怎么做"，给用户过目后再出关键帧。

| 结构 | 怎么测 | 做法 |
|---|---|---|
| 静止画 | 全画面帧差 <1.5，且每个小块（如 64×64）的峰值差也 <6（只看全画面会把说话、眨眼当静止） | 定格一张关键帧 |
| 几张静止画硬切 | 整帧帧差只有几个尖峰，且尖峰处**连背景一起换** | 每张一张关键帧 |
| 大画幅运镜 | 逐帧全分辨率相位相关，累计位移拼回整图，残差 <4；甩镜（每帧上百像素）也在同一张图上 | 拼原片画布 → Codex 一次改整张 → 去噪、放大回画布尺寸 → 按实测位移逐帧裁切；甩镜也在同一张画布上加运动模糊 |
| 图层插入/移动 | 只有一块区域变化，其余区域帧差 <1 | 底图沿用上一张，图层单独 Codex 换角；遮罩取原片变化区域，需用户同意 |
| 前景叠层 | 人物区域不变，只有一块前景/道具在动 | 人物一张固定画面，前景从原片逐帧叠上 |
| 背景不动、人物按原画节奏换画 | 背景区域帧差 <1，人物区域每 2–3 帧跳一次 | 一条 H3 链 + 按原片节奏选帧（每段原画区间选最清楚的一帧）；不逐张出 Codex 图 |
| 转场换画 | 帧差尖峰，但前后是同一动作的延续 | 一条穿过转场的 H3 链，在换画处锁帧；H3 揉糊的换画帧，从同一时刻的其他生成里选干净帧 |
| 连续运动 | 其余 | H3 |

**结构分类的教训（第三段实测）：** 原片用了"大画幅运镜"（开头一张竖长原画斜移、35–40 秒四人一张横向长卷）、"图层插入"（杂志一帧弹入）、"背景不动的一拍三"（抬头）、"两镜共用背景"（抬头和仰头笑）、"转场换画"（跃起 → Q 版翻滚 → 落地）。旧版分类只有三类，这些只能硬套成"连续运动"或"静止画"，七轮返修里有八个问题出在这里。抬头一镜先后试了 6 张 Codex 定格（背景闪）、H3 锁 6 张（背景每张偏 1 px）、分层合成（人物颤），最后才发现它和下一镜是同一张天空，改成一条链。

```python
# 大画幅运镜：全分辨率相位相关，累计位移后拼图，看残差
(dx, dy), r = cv2.phaseCorrelate(prev_gray, cur_gray)
# 两镜是否共用背景：交界处背景区域（避开人物）的帧差
bg_jump = np.abs(a[bg] - b[bg]).mean()   # < 2 视为同一张背景
```

**动静分类的教训（第二分钟实测）：**
- 只拆了镜头、没填这一列，结果 5 个原作是静止画的镜头都跑了 H3。H3 给它们加了原作没有的小动作，其中一个镜头还只画了一张关键帧，可原作其实是两张画。
- 另有一个外套甩过画面的转场，原作里人物完全不动，却被逐帧重画，头发每帧都在变。
- 这三类错误都是用户发现的，占了这一分钟返修的约三分之一。

```python
d = [np.abs(src[k-1][20:-20, 20:-20].astype(np.int16) - src[k][20:-20, 20:-20].astype(np.int16)).mean() for k in range(1, len(src))]
```

## 3. 生产参数

以下是实测值，换项目或换设备要重新量。

| 项 | 实测依据 | 默认 |
|---|---|---|
| 出图后端 | 用户可能禁用某个后端：它出的关键帧角形、发色悄悄跑偏，整批重做 | 写明只用哪个；GPT / Codex 出图后必跑 [gpt-anime-denoise](https://github.com/CXP-2024/gpt-anime-denoise)（默认 `esrgan60_l0`），见 [review-and-delivery.md](review-and-delivery.md)"去鱼鳞纹与光照" |
| 关键帧分辨率 | Codex 输出约 1672×941，小脸糊 | 小脸关键帧先做 ×4 动漫超分，再给 H3 |
| H3 分辨率 | 脸宽约 100 px 时低分辨率加超分，眼睛不行 | 脸小：1920×1088 直出。大头、背影、无脸：可在本地卡 1280×736 跑，再 ESRGAN 到 1080 |
| 段长 | 每接续一次，脸部清晰度掉 35–40% | 每段用满 39 帧；不为省显存改成 22 帧一段 |
| 步数 | 8/12/20 步画质相当，动作幅度随步数降 | 慢镜 8 步；快动作 12 步加默认稀疏；头发飘动、背影 20 步 |
| 设备 | 云卡按小时计费，等决策时也在计费 | 写明每次开机上限、用完删机；排好队列再问用户 |

## 4. 参考图按镜头比例截

给出图模型的定稿参考图，要截成**和目标镜头一样的比例和裁切**。

**反例：** 只截定稿的头部（到耳朵下方就停）。模型会自己补后面的头发：
- 一次补成往两边张开的大扇形，杂乱盘绕；
- 改提示词后又补成过窄的直发。

改了三版，按比例截之后一次通过。

**截法：**
1. 在原片这一帧量三个点：头宽、头部中心 x、后颈（衣领）y。脸可见时可以改用眼距和下巴。
2. 在定稿上量同样三个点；后颈被头发挡住时，从正面定稿量衣领高度。
3. 缩放 `s = 原片头宽 / 定稿头宽`，再平移，让头部中心和后颈对齐，截出 16:9：

```python
s = src_head_w / ref_head_w
x0 = ref_head_cx - src_head_cx / s
y0 = ref_neck_y - src_neck_y / s
M = np.float32([[s, 0, -x0 * s], [0, s, -y0 * s]])
crop = cv2.warpAffine(ref, M, (1920, 1080), flags=cv2.INTER_LANCZOS4, borderMode=cv2.BORDER_REPLICATE)
```

4. 和原片做 50% 叠加，检查头顶裁切、耳朵和肩膀的高度对得上，再给出图模型。
5. 看清这个比例下实际能看到什么，例如发梢的浅色到底露不露、肩膀露多少，按看到的写进提示词，不凭印象写"看不到"。

**脸小的镜头另加一栏原片脸部放大图**，用来定脸型和眼距。定稿是大特写时，眼距照搬到远景小脸上，双眼会超出脸。

## 5. H3 做不到、要事先定做法的镜头

| 现象 | 实测 | 事先和用户定的做法 |
|---|---|---|
| 快速转身、大幅低头（一拍二） | H3 跟不上，动作提前、拖影或不动 | 背景也跟着换（硬切）时：按原片每张原画逐张 Codex 重画，定格段沿用同一张。**背景不动时不要逐张重画**（背景闪、人物颤，第三段实测）：一条 H3 链按原片节奏选帧；姿势不到位就在换画处锁"用同一张已审关键帧只改姿势"做出的帧；或保留原片 |
| 一拍二/三的抬头、换姿势（背景不动） | 逐张 Codex 定格：天空每张重画，换画时背景跳 3–5（原片约 2）；H3 锁 6 张：背景每张偏约 1 px，像抽搐 | 一条 H3 链从含她的已审关键帧倒推，按原片节奏选帧 |
| 很短的转场（3–6 帧） | 单独成段时 H3 几乎不动；一条链跨原片换画时会把两张画揉糊 | 跑一条穿过转场的长段，换画处锁帧；糊的换画帧从其他生成里选 |
| 彩色 → 铅笔素描叠化 | 从彩色起点做不出褪色，试两次都是彩色 | 素描帧单独画，用 H3 过渡段接；或保留原片 |
| 小尺寸口型（脸宽约 100 px） | 嘴只有大张和闭两档，6 种提示词写法都试过 | 人物和镜头都静止：同一条 take 里按原片逐帧档位复用嘴部像素。在动：提示词写秒级开口区间，接受大致对齐 |
| 眼睛大特写 | 被拉远成半脸、凭空造场景 | 首尾锁定：同一关键帧作 Picture 1 和段末 guide |
| 手持抖动 | 提示词夸大到"3% 画宽"才出来约一半幅度 | 合成时迁移原片高频轨迹 |
| 多层运镜 | 整幅画幅平移，人物位置偏几十像素（前景实际移动 422 px，画幅移了 490 px） | 先分别量前景人物和背景的移动量，再定裁切路径 |
| 快速甩镜交界 | 交界 5–6 帧糊成一团 | 保留原片或接受 |
| 长链里角色出画 | 别的角色顶到她的位置，或画回原作角色 | 每段提示词只写当时在场的人；段末加经核对的身份引导帧 |

## 6. 返修怎么收

- **分组交付。** 先交难点镜头组（开场、群像、特写、背影）的静帧和片段，用户一次提完这一组的问题，改完再交下一组。不要每轮重渲整片、让用户从头找问题。
- **每轮附自检表。** 写清哪些项量过、数值多少，哪些没查。没查的不说"已对齐"。
- **看得见的瑕疵不写成"遗留"就交。** 第三段每轮写的"遗留"（残影、糊帧、接缝跳），用户下一轮几乎都指出来了。还有次数和机时就先修；修不了就在交付时作为问题直接问用户要不要换做法。
- **规则互相冲突时先停下问。** 两条规则给出相反做法时（如"每张静止画一张关键帧"和"一镜一锚"），先按实测判断哪条适用，拿不准就问用户，别按字面硬套一条。
- **按层归因。** 先找最早出错的那一层（规格 → 参考图 → 提示词 → 关键帧 → H3 → 选帧 → 合成），在那一层修，并把结论补进规格书或测量表。
- **只在出错的那一层改。** 只改眼睛时不要整张重画，否则已认可的部分又会变。
