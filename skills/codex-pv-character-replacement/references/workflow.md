# 项目流程与状态

## 1. 固定输入，而不是固定旧决定

用一个配置记录项目根、母带文件/hash、fps或PTS、范围[start,end)、声音、角色表版本、可写目录、保护文件、工具入口、GPU配置与最终输出。路径可相对项目根；生产脚本不能依赖作者电脑盘符。

同名PV的不同平台版可能剪辑、帧数、歌词和名字卡都不同。先比较母带，不因备用版无字就逐镜混用。非24fps素材不要套案例的24；可变帧率先建立PTS映射，若重采样需显式记录。

区分：
- original_source：动作、相机、原画的真值。
- approved_baseline：最近被用户认可的替换版本，局部修复从它出发。
- candidate：技术生成完但未被采用。
- selected：本次装配选用，仍可能待用户审片。
- accepted/rejected：用户或指定审核者的明确结论。

文件时间最新不等于可用；“complete”只表示任务完成。装配只能从当前有效的选用清单取素材，撤回时使旧选择失效。

## 2. 切镜、角色与文字清单

场景检测只产生候选。查看每个边界前后至少一个完整转场；白闪、推拉、擦除、阵列与溶解都可能被漏切/错切。首中尾缩略图做总览，复杂镜头加密，不以三帧概括整镜。

每镜记录 id、start/end、shot_type、route、tone或衣装政策、cast、保留角色、文字层、转场上下文、状态。客串/背影/剪影也要明确身份；空cast不能默认为不用审图，因为用户可能后来授权了新角色。

文字清单包含名字、大/小声优字、歌词、标题、staff、拟声词、版权及环境文字。每项记录范围、区域、动作和 replace/keep/erase。不用“擦掉所有文字”抹掉用户要保留的拟声词或真实署名。

## 3. 先确定小样，再扩展

先做定妆照与代表性关键帧：近景头发、侧脸饰品、Q版、多人物、远景、复杂入退场各选实际需要的样例。先批准身份/画风，再生成依赖它的镜头。一个坏身份锚会污染所有视频，后端调色救不回。

路线冒烟使用本机真实输入、真实峰值显存及真实时间。模型下载成功、工作流节点存在、缓存CPU roundtrip都不等于推理成功。下载记录版本与校验和；新增配置/工作流，不覆盖已验证环境。

## 4. 生产组织

用户选择串行时：一组生成→工程自检→连贯对比→用户反馈→再下一组。允许批量时按依赖执行：已审身份→锚帧→对应提示词→审核包→GPU→自检。批量规模按用户要求和返工率调整。

只有明确允许时才并行代理；每个执行者有独立镜头目录，统一汇总计划，GPU仍严格串行。遇到多数批次返工时先减小批量校准，不以吞吐掩盖错误传播。

存在审核inbox时，每任务完成、每次提交批次前读新增条目，以稳定条目ID/时间+正文hash记已处理；收到不等于处理完成。撤回与修订可覆盖同一镜头，逐条标记具体执行结果。导演原文件只读。

## 5. 报告与范围结束

每阶段/组记录：
- 输入/输出、选用版本、源区间与模型规格。
- 端到端耗时、GPU时间与CPU时间分开；整卡显存不叫模型独占显存。
- 生图云端型号/显存若工具不返回则记未核实/N/A。
- 明确返修原因、未采用候选与审核状态。
- 可打开的输出路径、原速对比、最终帧台账。

不要依照旧阶段停点打断当前已授权连续生产；也不要越过用户本轮明确要求的“样张后停”“只出图不跑H3”。独立彩蛋单独装配，复用已认可主角特写，不改正片。
